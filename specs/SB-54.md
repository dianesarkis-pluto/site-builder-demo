# SB-54 — Content report: reconcile history per page

## Scope

The weekly content report should show, per page, when it was last reconciled
and what drift was corrected, read from the `.reconcile-history/` snapshots
that the `/reconcile` procedure writes. A missing history directory must
produce an empty report rather than throwing.

## Acceptance criteria (the contract)

1. `lib/report.js` reads `.reconcile-history/` and returns
   `{pageId, when, driftCorrected}` per page.
2. A missing `.reconcile-history/` directory yields an empty report, no throw.
3. Tests use fixture snapshots.
4. No change to publish-path behavior.

## Contracts

`reconcileReport(historyDir?)` → `Array<{pageId, when, driftCorrected}>`

- Reads every `*.json` snapshot in `historyDir` (default: `.reconcile-history/`
  resolved relative to the module, matching the path `/reconcile` writes to).
- Each snapshot has the shape `/reconcile` writes:
  `{ pageId, previousPublishedRev, draftRev, driftPct, edits }`. The reconcile
  timestamp is **not** a field in the snapshot body — it lives in the filename
  `<pageId>-<iso-timestamp>.json`. `when` is parsed from the filename;
  `driftCorrected` is the snapshot's `driftPct`; `pageId` is read from the
  snapshot body.
- One entry **per page**: a page reconciled more than once keeps only its most
  recent snapshot (latest `when`, compared lexicographically — ISO-8601 sorts
  correctly as strings).
- Output is sorted by `pageId` for deterministic report rows.
- Read-only. Never imports, calls, or touches the publish/sync path
  (`applySync`, `PAGES`, `lib/pages.js` mutation).

## Edge cases

- Missing `.reconcile-history/` directory (`ENOENT`) → `[]`, no throw (AC2).
  This is the real current state of the repo.
- Empty directory → `[]`.
- Non-`.json` files in the directory are ignored.
- Multiple snapshots for one page → newest wins.
- Filenames contain dashes in both the page id (`PG-0042`) and the ISO
  timestamp; `when` is recovered by stripping the `pageId` prefix (read from
  the body) and the `.json` suffix, which avoids ambiguous dash-splitting.

## Out of scope

- **Listing never-reconciled pages.** The ticket _description_ mentions "Pages
  never reconciled are listed as such," but this is **not** among the four
  acceptance criteria, and such pages have no snapshot and therefore no `when`
  or `driftCorrected`. The report covers pages that have reconcile history; a
  consumer can cross-reference `listPages()` for the never-reconciled set. If
  the never-reconciled listing is wanted in the report itself, it should be a
  follow-up ticket with its own acceptance criteria.
- Any change to `lib/pages.js`, `lib/blocks.js`, or the publish/sync path.
- Computing or re-deriving drift — the report reports the `driftPct` the
  snapshot already recorded.
